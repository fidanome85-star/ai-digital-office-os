# ADR 0001 — Phase 1 implementation choices

**Status:** Accepted
**Date:** 2026-08-30

## Context

The v1.4 blueprint and implementation scaffold are technology-agnostic and
state a Node.js/TypeScript + PostgreSQL assumption without mandating it.
Phase 1 (database schema + domain model + auth) needed concrete choices the
spec deliberately left open.

## Decisions

1. **pnpm workspaces monorepo**, TypeScript, Node 20+. Matches the
   scaffold's stated assumption; no reason to diverge without a driving
   requirement.

2. **Domain model generated by introspecting the live schema
   (`information_schema`), not by regex-parsing the migration SQL text.**
   The clause-69 consistency gate only needs the *result* of applying the
   migrations to match the domain model — introspecting the actual running
   schema is more accurate than parsing SQL syntax (handles multi-line
   definitions, inline constraints, and any Postgres-specific syntax
   correctly by construction, since Postgres itself parsed it first).

3. **A dedicated non-superuser `ai_office_app` role (migration 0022),
   separate from the migration-owning role.** Postgres exempts table
   owners and superusers from Row-Level Security unless `FORCE ROW LEVEL
   SECURITY` is set. Without a non-owning role, RLS policies could not be
   tested at all, and any Phase-1 claim of "RLS verified" would be false.
   Every application service must connect via `APP_DATABASE_URL`, never
   `DATABASE_URL` (the migration/owner connection).

4. **`jose` for JWT/JWKS verification**, over `jsonwebtoken` +
   `jwks-rsa`. `jose`'s `createRemoteJWKSet` handles key-rotation-by-`kid`
   natively with built-in caching, directly closing the integrity review's
   MEDIUM finding on JWKS rotation without hand-rolled cache logic.

5. **Custom `tenant_id` and `principal_type` JWT claims, required on every
   token.** The blueprint distinguishes human and service (agent/M2M)
   callers throughout (approvals, audit events, policy decisions). That
   distinction has to be carried on the token itself, not inferred later
   from context that may not be available downstream.

6. **`AsyncLocalStorage` for request-scoped tenant context**
   (`packages/auth/src/tenant-context.ts`), verified under concurrent load
   in tests, as the bridge between `packages/auth` and the RLS session
   variable (`app.current_tenant_id`) — no service-layer code should ever
   thread a tenant id through function parameters by hand.

## Consequences

- Every future service must connect to Postgres as `ai_office_app`, and
  must call `SELECT set_config('app.current_tenant_id', $1, false)` (or
  the transactional `SET LOCAL` form once a pooled-transaction db-client
  wrapper exists) at the start of every request — there is no default-safe
  fallback; forgetting this makes RLS a no-op for that connection.
- `pnpm domain-model:generate` requires a migrated database to run against
  (`DATABASE_URL`) — it cannot run standalone. CI runs migrations first.
